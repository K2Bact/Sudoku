## 왜 통합했나

`PROJECT_IDEAS_AND_BACKLOG.md` 의 "출시 직전 필수 게이트" 4개 중 **3개가 이미
해결됐는데도 "대기 중" 으로 적혀 있었습니다.** 코드를 직접 확인하고 알았습니다.

| 문서가 말한 것 | 실제 코드 |
|---|---|
| AdMob 테스트 ID 교체 대기 | 테스트 ID 테이블 자체가 없음. `.env` 한 줄로 전환 |
| 가상 랭커 → 실제 데이터 전환 대기 | 이미 백분위 라벨(`TOP 0.1%`)로 교체됨 |

### 2026-09-09 — 검사 체계를 뜯어고쳤습니다

**초록불 아래에 기준점이 없었습니다.** 파이프라인이 34단계 전부 통과하는 동안
13개 언어 중 둘이 깨져 있었고, 검사는 그것을 잡을 수 없었습니다 — **검사 자신이
그 중복의 일부였기 때문입니다.**

```js
const langs = ['ko', 'en', 'ja', 'zh', 'es'];   // test_practice_missions.js
```

이 줄은 로케일 목록을 **검사하는 것이 아니라 그 목록의 사본**입니다. 사본은 원본이
바뀌는 것을 감지할 수 없고, 그래서 앱이 13개로 자라는 내내 초록이었습니다.

| 무엇을 | 어떻게 |
|---|---|
| 로케일 단일 출처 | `scripts/lib/locales.js` — `src/i18n/locales/` 를 읽고 **언어 선택기와 교차 검증**. 로케일 파일과 버튼 목록의 일치를 아무도 보고 있지 않았습니다 |
| 아카데미 코드 통일 | `zh`/`es` → `zh-CN`/`zh-TW`/`es-ES` (380블록 × 13언어). 정규화 3곳 제거, 조회를 `pickLocale` 하나로 |
| **게이트 2-16 신설** | 아카데미 문자열 4,940개를 l10n 엔진에 편입 (축 반전 어댑터) |
| **게이트 2-17 신설** | 로케일 목록을 코드에 적으면 빌드 실패 |
| 게이트 4 확장 | 금지 문자 52 → 165자 |

### 이 과정에서 나온 실제 결함

```
zh-TW 아카데미 380블록    비어 있었음 → 채움 (손번역 10개는 그대로 보존)
zh-TW UI 로케일          간체 33자 섞임   ← "완역" 으로 알려졌던 파일
zh-CN 아카데미           번체 17자 섞임
es-ES 아카데미           키 불일치로 조회 실패
```

**변형 하나가 게이트를 잡았습니다.** 번체 `後` 를 간체 `后` 로 바꾼 변형이 통과했고,
원인은 `后` 가 게이트 4 목록에 없었던 것이었습니다 — **"간체 검사" 라는 이름을 달고
실제로는 52자만 보고 있었습니다.** 넓히자 위의 33자와 17자가 딸려 나왔습니다.

**접근성이 진짜 값어치입니다.** 손을 쓰기 어려운 이용자에게는 편의 기능이 아니라

명령 후보 (기존 키보드 매핑 O-3 과 1:1 로 맞추면 설계가 한 벌로 끝납니다):

```

"메모"                  메모 모드 토글
"힌트"                  힌트
"일시정지"              일시정지
```

```
① 웹뷰에서 되는가
   webkitSpeechRecognition 은 Capacitor 웹뷰에서 안 될 가능성이 큽니다.
   @capacitor-community/speech-recognition 같은 네이티브 플러그인이 필요할 수 있음

② 오프라인에서 되는가

   쓸 수 있는지가 갈림길입니다

③ 13개 언어를 어떻게 할 것인가
   숫자만 인식하면 언어 부담이 훨씬 작아집니다. "3행 7열" 같은 문장을 받으면
   13개 언어의 문법을 각각 다뤄야 합니다.
   → 1단계는 숫자만, 2단계에서 이동 명령 검토
```

**마이크 권한은 정책 신고에 영향을 줍니다.** `RECORD_AUDIO` 를 추가하면 데이터
보안 양식과 개인정보처리방침을 함께 고쳐야 합니다(음성을 어디로도 보내지 않는다면
