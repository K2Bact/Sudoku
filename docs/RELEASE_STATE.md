대화는 압축되지만 이 파일은 압축되지 않는다. **"이거 했나?" 를 사용자에게 되묻기
전에 여기부터 읽는다.**

### 🔴 승인 ≠ 출시

콘솔 문구가 *"프로덕션 트랙을 **통해** 게임을 제공할 수 **있습니다**"* 라고 말한다.
**자격을 받았다는 뜻이지 나갔다는 뜻이 아니다.** 화면 제목이 `버전 생성 및 게시` 인
것이 그 증거 — 그것이 아직 하지 않은 일이다.

**아직 아무 일반 이용자도 이 앱을 받을 수 없다.**

**급하지 않다** — 앱이 망가진 것이 아니라 문자 체계가 틀린 것이고, 몇 달째 그랬다.
다음 빌드에 자동으로 따라오므로 이것만을 위해 재빌드하지 않는다.

### 버전 이력의 함정

**1.2.2 (versionCode 16) 는 출시된 적이 없다.** 2026-09-03 에 업로드만 되고
`임시` 상태로 서 있었다. 업로드와 출시는 다른 단계이고 **`출시 시작` 을 누르지
않으면 아무한테도 가지 않는다.**

그래서 1.2.1 은 이 저장소의 최초 커밋(`1c8602b`, 2026-09-01 21:59)보다 오래됐다.
저장소에서 고친 것이 하나도 들어있지 않다.

## 출시 계획 — 가장 안전한 경로 (2026-09-11 결정)

**첫 출시이므로 프로덕션 직행을 하지 않는다.** 승인과 함께 공개 테스트(오픈 베타)
트랙도 열렸고, 그 한 단계를 거친다.

```
A. 공개 테스트     누구나 참여 가능하되 "얼리 액세스" 표시가 붙는다
                  실제 광고 수익이 발생하고, 문제가 생기면 조용히 내릴 수 있다
B. 프로덕션        전 세계 공개. 되돌리는 비용이 크다
```

**A 를 먼저 하는 이유는 광고다.** 실제 광고 단위를 처음 켜는 판이고, 무효 트래픽이나
정책 문제가 나오면 그 이력이 프로덕션에 남지 않는 편이 낫다.

### 단계

```
1. AdMob 앱 등록 → 실제 광고 단위 3개 생성
2. 인앱 상품 remove_ads_permanent 생성        ← 코드의 값과 반드시 일치. 변경 불가
3. .env         BANNER / INTERSTITIAL / REWARDED 단위 ID    3곳
4. 매니페스트    APPLICATION_ID                             1곳
5. .env         VITE_ADMOB_TESTING=false
6. .env         VITE_BILLING_PROVIDER=play                 (2번을 했을 때만)
7. app-ads.txt  → k2bact.github.io 루트                     ← 현재 404
8. 1.2.4 (versionCode 18) 빌드
9. 공개 테스트 트랙 → 출시 시작
10. 며칠 관찰 → 문제 없으면 프로덕션 트랙으로 승격
```

**프로덕션으로 갈 때는 단계적 출시를 쓴다.** 콘솔이 이용자 비율(5% → 20% → 50% →
100%)을 정할 수 있게 해주며, 중간에 멈출 수 있다.

### 🔴 실제 광고 ID 를 켠 뒤 절대 하지 말 것

```
자기 기기에서 광고를 클릭하지 않는다
지인에게 "광고 좀 눌러줘" 라고 부탁하지 않는다
```

**무효 트래픽이고 AdMob 계정 정지 사유다.** 지금까지 테스트 단위 ID 를 쓴 이유가
정확히 이것이며, 실제 단위로 바꾸는 순간 그 안전장치가 사라진다.

화면 확인이 필요하면 **광고가 뜨는 것까지만 보고 누르지 않는다.**

## 하면 안 되는 것

**자기 광고를 누르지 않는다** — 위 출시 계획에 적었다. 현재 샘플
ID(`ca-app-pub-3940256099942544/…`)는 항상 테스트 광고를 반환하므로 눌러도 되지만,
실제 단위로 바꾸는 순간 그 안전장치가 사라진다.

**`minifyEnabled` 를 켠 채로 실기 재검증 없이 출시하지 않는다.** 현재 `false` 다.
R8 이 리플렉션으로 부르는 광고/UMP 클래스를 잘라내면 광고가 조용히 죽는다. 켤 거면
배너·리워드·전면·동의를 전부 다시 확인해야 한다. 콘솔 경고 2건(APK 크기 · 난독화
매핑 없음)이 이것 때문이고, **둘 다 `오류` 가 아니라 `경고` 라 출시를 막지 않는다.**

**업로드하고 `출시 시작` 을 안 누르지 않는다.** 1.2.2 가 그렇게 멈췄다.

## 아직 판단이 안 끝난 것

**데이터 보안 2단계 — "사용자가 앱 외부에서 만든 계정으로 앱에 로그인할 수
있나요?" 가 `아니요` 다.** 앱에는 Play 게임즈 로그인(`playGamesService.js:81`)이
있고 `cloudSyncService` 가 Play 게임즈 저장 슬롯에 백업한다. 구글이 이걸 "앱 계정
로그인" 으로 보는지 미확인. `예` 로 바꾸면 데이터 삭제 수단 요구가 따라올 수 있다.
**오늘 새로 생긴 위험은 아니다** — 이 답은 오래전부터 그 상태였다.

**~~`app_common` 에 원격이 없다~~** — 2026-09-09 해결. `K2Bact/app-common` (private)
에 백업됐다. 이 저장소의 빌드를 막을 수 있는 l10n 게이트가 거기 있으므로 백업이
필요했다.

**테스터 피드백 5건 중 1건은 커밋 기록이 없다 — 다만 재현되지 않는다.**
*"게임 후 결과 표시가 진행도인지 뭔지 알 수 없다"* 에 대응하는 커밋이 일지·백로그
어디에도 없다. 나머지 넷은 코드로 확인했다 (1v1 통신 `a5e9703` · 힌트 동기화
`0cd7b97` · AI 난이도 세분화 · 다국어 넘침).

2026-09-08 에 게임 종료 후 뜨는 두 화면을 직접 읽었고, **라벨 없는 값은 없었다.**

```
VictoryModal        rankLabel · difficultyLabel · timeLabel · mistakesLabel
                    모든 수치에 라벨 + 단위
BattleResultModal   ratingChange 라벨 + "±N MMR" (폴백까지 항상 숫자를 그림)
```

통계 화면이 한 번 다시 쓰이면서(`screens.stats.tabs.*` → `achievements.*`) 같이
정리됐을 가능성이 높다. **"확인했으나 재현 안 됨" 으로 남긴다** — 사용자도 어느
화면이었는지 기억하지 못한다. 테스터가 다시 언급하면 그때 화면을 특정한다.

**`afterGameAd` 주석이 코드보다 넓게 말한다.** *"게임이 끝나는 두 경로 모두"* 라고
적혀 있지만 실제로는 승리 모달의 두 버튼뿐이고, 게임 오버는 광고를 안 거친다.
동작은 의도적이므로 **주석만** 고칠 것. (심사 중에는 손대지 않는다)
