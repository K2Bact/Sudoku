## 출시 계획 (2026-09-11 저녁 · 콘솔에서 확인하며 두 번 고침)

### 🔴 "공개 테스트 → 프로덕션" 은 성립하지 않는다

이 문서는 아침까지 그 경로를 적고 있었다. **틀렸다.** 콘솔이 막았다.

```
현재 공개 테스트가 제한됨
공개 테스트 버전을 만들 때는 프로덕션 버전이 있는 국가만 선택할 수 있습니다.
프로덕션 버전이 없는 국가에서 앱을 사용할 수 있도록 하려면
대신 사전 체험판 트랙을 만드세요.
```

**공개 테스트는 프로덕션을 전제로 한다.** 프로덕션 버전이 0개이므로 고를 수 있는
국가가 0개가 되어 트랙 자체를 쓸 수 없다. 순서가 거꾸로였다.

구글 도움말은 지금도 *"사전 체험판 앱(프로덕션에 게시되지 않은 새로운 앱)도
공개 테스트 버전을 찾아 설치할 수 있다"* 고 적고 있다. **화면이 도움말보다
최신이다.** 이 프로젝트에서 같은 일이 이번 주에만 세 번 있었다.

그러니 공개 테스트는 신규 앱의 출시 전 단계가 아니라, **이미 프로덕션에 있는 앱이
새 시장을 시험할 때** 쓰는 도구로 이해해야 한다.

### 실제 경로

```
비공개 테스트 ──→ 프로덕션
     ↑                  ↓
  지금 여기        그 뒤에야 공개 테스트를 쓸 수 있다
```

### 현재 상태

```
비공개 테스트   1.2.4 (18) 게시됨 · 2026-09-11 · 기기 설치 확인됨
               실제 광고 서빙 확인 (잡코리아 배너) · 배너 위치 정상
               ⚠️ 개발 기기는 테스트 등록 안 된 상태 — 광고 클릭 금지
공개 테스트     쓸 수 없음 (프로덕션 없음)
사전 체험판     미확인 — 콘솔이 링크를 보여주지만 눌러보지 않았다
프로덕션        비어 있음. 액세스는 승인됨
```

**사전 체험판(Early access)** 은 대안이 될 수 있으나 성격이 다르다. 공식 문서에서
공개 테스트와 다른 점 세 가지:

```
· Early access users are automatically moved to production when your app launches
· Early access users can leave ratings and reviews for your app on Google Play
· You can acquire users through multiple methods in a single Early access track
```

**가운데가 중요하다 — 별점과 리뷰가 공개로 남는다.** 공개 테스트는 남지 않는다.
실제 광고를 처음 켠 판이고 app-ads.txt 검증도 끝나지 않은 지금은, 리뷰가 남는
트랙으로 가기 전에 확인할 것이 있다.

> 문서에 *"The Early access track is currently only available to select developers"*
> 라고 되어 있다. 콘솔이 링크를 보여줬으므로 대상일 가능성이 높지만 **확인하지 않았다.**

### 🔴 광고는 프로덕션 이후에 풀린다 — 순서를 세 번 틀린 끝에 확인 (2026-09-11)

**이 문서는 "app-ads.txt 검증이 끝나면 프로덕션" 이라고 적고 있었다. 불가능한
순서다.** 검증도 승인도 앱이 스토어에 공개된 뒤에야 시작된다.

구글 문서 세 곳이 같은 말을 한다. 원문 그대로 옮긴다.

> **All Android apps must be publicly available in a supported store in order to
> link to AdMob.**
> **Your app must be published. This means that your app is available to users.**
> — [App readiness](https://support.google.com/admob/answer/10564477?hl=en)

> **The AdMob app-ads.txt crawler checks for your app-ads.txt file based on the
> developer website in your app's store listing.**
> — [app-ads.txt 설정](https://support.google.com/admob/answer/9363762?hl=en)

> **Apps won't be able to fully serve ads until they're verified with an
> app-ads.txt file and approved after the app readiness review.**
> **Once your app is verified, the app readiness review will begin.**
> — [2025년 1월 요건](https://support.google.com/admob/answer/14538460?hl=en)

#### 실제 순서

```
1. 프로덕션 출시                  ← 나머지 전부가 이것에 걸려 있다
2. AdMob → 앱 스토어 연결          "publicly available" 이어야 연결된다
3. app-ads.txt 크롤링·검증        문서는 24시간, 콘솔 화면은 "도메인 URL 변경 감지까지 최대 7일"
4. 앱 준비 상태 심사               검증이 끝나야 시작. 보통 2~3일
5. 승인 → 광고 정상 게재           그전까지는 limited ad serving
```

**1번 전에는 2·3·4 중 어느 것도 진행되지 않는다.** 비공개 테스트로 기다리는 것은
끝나지 않을 일을 기다리는 것이다.

#### 왜 세 번이나 틀렸는가 — 기전을 적어둔다

문서를 **하나씩 따로 읽고 순서를 조립했다.**

```
app-ads.txt 문서   "검증돼야 광고가 완전히 서빙된다"      → 출시 전에 해야겠네
앱 준비 문서       "승인돼야 광고가 서빙된다"            → 이것도 출시 전에
연결 문서          "스토어에 공개돼 있어야 연결된다"      ← 이 줄을 읽지 않았다
```

앞의 둘만 보면 둘 다 "출시 전 준비" 로 읽힌다. **세 번째 문장이 그 둘을 출시
이후로 밀어버리는데, 그 문장을 찾기 전에 순서를 만들었다.**

인앱 결제에서도 같은 일이 있었다. 코드 주석이 "상품 생성 → 플러그인 설치" 라고
적고 있었고, 콘솔은 결제 권한이 든 빌드가 먼저라고 말했다.

> **조각조각 맞는 사실로 틀린 순서를 만들 수 있다.** 순서를 물을 때는 각 단계의
> 설명이 아니라 **전제 조건**을 찾아야 한다 — "무엇을 하면 되는가" 가 아니라
> "무엇이 있어야 이것을 할 수 있는가".

#### 첫 프로덕션 — 범위는 국가로 줄인다

비율 출시는 첫 출시에 쓸 수 없다 (확인 완료).

> Rollout percentage options are unavailable for a first release.
> — [Play Console 고객센터](https://support.google.com/googleplay/android-developer/answer/6346149)

**2026-09-11 결정: 한국만으로 시작하고 하나씩 늘린다.** 넓히는 것은 나중에 쉽고,
좁히는 것은 이미 받은 이용자를 잃는 일이다.

**무효 트래픽이고 AdMob 계정 정지 사유다.** 지금까지 테스트 단위 ID 를 쓴 이유가

#### 테스트 기기 등록 — 해시는 고정된 값이 아니다 (2026-09-11 실패 기록)

`VITE_ADMOB_TEST_DEVICE_IDS` 에 기기 해시를 넣으면 그 기기만 테스트 광고를 받고,
눌러도 무효 트래픽이 되지 않는다. 그것이 "앱을 깔지 말라" 대신 구글이 주는 답이다.

**그런데 그 해시는 기기의 광고 ID 에서 나오고, 광고 ID 는 재발급된다.**

2026-09-11 에 실제로 이렇게 어긋났다.

```
B75B079756F1D2A2CCEC0F24DB1D2CF7   기기에서 뽑아 1.2.4 빌드에 넣은 값
DD0A1A5CB9BB60607CA2997FACA4233B   앱을 지웠다 다시 깐 뒤 기기가 쓰는 값
```

서명이 달라 덮어쓰기가 안 되자 **앱을 수동으로 지우고 재설치**했고, 그 과정에서
광고 ID 가 새로 발급됐다. 빌드 안의 해시는 더 이상 이 기기를 가리키지 않는다.
결과: 등록되지 않은 기기 → **실제 광고**. 화면에 잡코리아 배너가 떴고 라벨이 없었다.

**순서를 이렇게 잡을 것.**

```
1. 기기 해시를 뽑는다      adb logcat | findstr "RequestConfiguration.Builder"
2. .env 에 넣고 빌드한다
3. 그 빌드를 **플레이스토어 업데이트로** 받는다   ← 지우고 깔지 않는다
4. 배너에 "Test Ad" 라벨이 보이는지 확인한다
```

3번이 요점이다. **지우고 깔면 1번이 무효가 된다.** 로컬 빌드는 업로드 키로,
스토어 배포본은 구글 키로 서명되므로 덮어쓰기가 안 되고, 그래서 지우고 깔고
싶어진다 — 그 유혹이 정확히 이 실패의 입구다.

해시가 어긋났는지는 로그로 즉시 알 수 있다. SDK 가 매 요청마다 **지금 이 기기의**
해시를 찍어주므로, 빌드에 넣은 값과 다르면 등록이 안 된 것이다.

> **라벨을 보기 전까지는 등록됐다고 간주하지 않는다.** 값이 빌드에 들어간 것과
> 화면이 테스트 광고를 받는 것은 다른 사실이다.

ID(`ca-app-pub-3940256099942544/…`)는 항상 테스트 광고를 반환하므로 눌러도 되지만,
실제 단위로 바꾸는 순간 그 안전장치가 사라진다.

**`minifyEnabled` 를 켠 채로 실기 재검증 없이 출시하지 않는다.** 현재 `false` 다.
R8 이 리플렉션으로 부르는 광고/UMP 클래스를 잘라내면 광고가 조용히 죽는다. 켤 거면
배너·리워드·전면·동의를 전부 다시 확인해야 한다. 콘솔 경고 2건(APK 크기 · 난독화
매핑 없음)이 이것 때문이고, **둘 다 `오류` 가 아니라 `경고` 라 출시를 막지 않는다.**

**업로드하고 `출시 시작` 을 안 누르지 않는다.** 1.2.2 가 그렇게 멈췄다.
