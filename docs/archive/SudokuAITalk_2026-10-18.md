#### CH18-01 — 마지막 힌트와 승리 기록

**재현:** Lv.3, 300초, 힌트 사용 0, 빈칸 하나의 정통/킬러 저장을 각각 이어서 연다. 마지막을 직접 입력한 대조군은 힌트 5 유지·최고 기록 300초다. 같은 조건에서 힌트 버튼으로 끝낸 군은 **5→4 차감**, 승리 카드의 `data-reason="hint_used"`인데도 `bestTimes[3]=300`, `clearedLevels[3]=true`, 해당 종류의 고스트 `bestSeconds=300`이 남는다.

**원인 위치:** `src/hooks/useKeypadActions.js`의 `handleGetHint`는 `setHintsUsedCount(prev => prev + 1)` 직후 같은 렌더의 `handleInputNumber`를 호출한다(126–139행). 그 콜백은 갱신 전 `hintsUsedCount`를 `handleGameWinLogic`에 전달한다(`src/hooks/useGameInput.js`, 230–245행). 다음 렌더의 승리 모달은 갱신된 1을 읽으므로 화면과 이미 저장된 결과가 어긋난다. `recordEligibility` 함수 자체는 힌트 사용을 올바르게 거부한다.

**수정 방향:** 승리 처리에 넘길 이번 입력의 힌트 사용 사실을 동기적으로 확정한다. 정답 입력→판 완성→자격 판정→저장이 같은 사실을 읽어야 한다. 화면 문구를 지우거나 자격 조건을 완화하는 방식으로 덮지 않는다. 실제 Play Games에 오염된 점수가 전송된 것은 이번 검수에서 확인하지 않았다. 로컬 Logic Score 입력 데이터가 잘못 저장되는 데까지 확인했다.

**기존 검사의 빈틈:** 2-21은 `handleGameWinLogic`에 `hintsUsed: 1`을 직접 넘겨 검사한다. 힌트 버튼→React 상태 갱신→마지막 칸 승리라는 연결은 검사하지 않는다. 향후 수정 시 이 버튼 경로를 3-8 또는 그에 맞는 기존 E2E에 넣어야 한다.

#### CH18-02 — 메모 모드의 힌트 소모

**재현:** 정통 저장의 빈칸을 선택하고 메모 버튼을 켠 뒤 힌트 버튼을 누른다. 지갑은 **5→4**, 저장된 `hintsUsedCount=1`이지만 선택 칸은 **0 그대로**, 해당 칸 메모에 정답 `[1]`만 생겼다. 정답 입력 없이 소비된 힌트를 다시 보상해 주는 경로는 없다.

**원인 위치:** `handleGetHint`가 일반 `handleInputNumber`를 그대로 호출하고, 그 함수는 `isNoteMode`이면 메모 분기에서 반환한다(`src/hooks/useGameInput.js`, 124–136행). 힌트 전용 정답 적용 경로가 없다. 문제는 외국어 문구의 자연스러움이 아니라 버튼의 실제 동작이다.

**수정 방향:** 힌트는 메모/숫자 우선 모드와 독립적으로 의도한 답 적용을 수행하도록 한다. 적용할 답이 실제로 존재하고 적용 가능할 때 소비하는지도 함께 확인한다. 코드 수정 후 메모 ON/OFF를 같은 퍼즐에서 대조한다.

#### CH18-03 — 데일리의 이어하기

**대조 재현:** 2026-10-18, 출석 보상은 이미 수령한 새 브라우저 상태에서 캘린더 오늘 칸을 눌러 데일리를 시작했다. 중단 없이 풀면 캘린더에 `2026-10-18.completed=true`, 지갑 **5→6**. 별도 새 상태에서 한 칸 입력 후 페이지를 재시작하고 홈의 이어하기로 나머지를 풀면 **승수는 1이지만 데일리 기록은 null, 지갑은 5 그대로**였다. 두 경우 모두 UI 입력으로 퍼즐을 완성했다.

**원인 위치:** 날짜는 `App`의 `activeDailyDateKey` 상태에만 있다(`src/App.jsx:28`). `useGameLifecycle`의 저장 객체에 날짜가 없고(73–99행), `resumeSavedGame`에서도 복원하지 않는다(`src/hooks/useSudokuGame.js:205`). 게다가 `handleStartSingleGame`은 이어하기를 포함해 `setActiveDailyDateKey(null)`을 먼저 호출한다(`src/hooks/useGameStarters.js:40`). 따라서 홈으로 나갔다 돌아오는 경로도 같은 날짜 연결을 잃을 수 있다. 이번 브라우저 비교는 **페이지 재시작** 경로를 직접 실행했다.

**수정 방향:** 진행 중인 판의 데일리 날짜를 저장·복원한다. 새 일반 판에서만 날짜를 비우고, 이어하기는 복원된 날짜를 유지해야 한다. 과거 날짜 퍼즐·날짜가 바뀐 뒤의 이어하기·일반 일일 미션도 각각 구분한다. 2-22의 저장 가능 여부 검사만으로는 이 경로를 보장하지 못한다.

#### CH18-04 — 스피드런 마지막 보너스와 저장값

**재현:** 300초·빈칸 두 개의 정통/킬러 스피드런을 각각 이어서 열고 두 칸을 3.5초 안에 맞힌다. 마지막 입력 직전 05:00 → 마지막 입력 후 머리와 승리 카드 **04:59**, 떠오르는 표시 **-1s (2 COMBO!)**. 하지만 `timeAttackBestTimes[3]=300`, `maxCombo=1`이다. 정통·킬러에서 같은 결과다.

**원인 위치:** `handleComboSuccess`의 `setTimerSeconds`·`setComboCount` 뒤 같은 `handleInputNumber`가 갱신 전의 `timerSeconds`·`comboCount`로 승리를 기록한다(`src/hooks/useGameInput.js:207–245`, `src/hooks/useGameTimer.js:90–100`). CH18-01과 같이 마지막 입력이 바꾼 사실보다 저장이 먼저 확정되는 계열이다. 자격이 올바른 판에서도 시간·콤보가 어긋난다는 별도 사용자 영향 때문에 구분했다.

**수정 방향:** 이번 입력을 반영한 최종 시간·콤보를 승리 기록과 화면이 함께 읽도록 한다. 2초 보너스와 마지막 콤보에서 업적 조건에 도달하는 경우도 회귀 대상으로 삼는다. 서바이벌의 마지막 보너스도 같은 호출 경로이지만, 이번 추가 대조에서 그것을 별도 결함으로 판정하지 않았다.

### 전체 QA와 검사 체계의 해석

**전체 QA 결과: `npm run qa` 60/60단계 통과, 종료 코드 0, 1270.1초(약 21분 10초).** 빠른 세트가 아니라 3-4~3-19 화면 검사까지 실행한 결과다. 단계 수는 이번 실행 로그의 완료 줄과 러너의 실제 호출 목록을 대조했다. ESLint는 오류 0·경고 6이며 경고를 고치는 변경은 하지 않았다.

전체 QA의 통과가 위 네 결함을 반박하지 않는다. QA가 실행한 조건은 통과했지만 마지막 힌트·메모 힌트·데일리 재시작·마지막 콤보의 연결 조건을 추가 재현했을 때는 문제가 드러났다. 「검사가 통과했다」와 「새 결함이 없다」를 같은 결론으로 쓰지 않는다.

- 첫 샌드박스 실행은 0-4b가 임시 Git 저장소의 `.git/config`에 쓰지 못해 종료됐다. 이 실행을 통과로 바꾸어 적거나 앱 기능 결함으로 집계하지 않는다. 필요한 권한으로 같은 전체 QA를 새로 실행했다.
- 기존 검사에서 언어 키·보간·스크립트 혼입·레이아웃은 검사한다. 사용자가 제외한 **원어민 어감·자연스러움**은 별도로 평가하지 않았다.
- 3-11의 러너 제목은 `every mission × 13 languages`, 마지막 출력도 모든 언어의 모든 연습을 확인한 듯 표현하지만, **구현은 한국어·아랍어 전수 + 다른 11개 언어의 레이아웃/단계 표본**이다. 파일 앞 주석에는 이 범위가 올바르게 설명돼 있다. 본 검수는 최종 통과 문장을 전수의 증거로 확대하지 않는다. 이것은 보고 범위의 주의점이며 위 기능 결함 수에 더하지 않았다.
- 이번 3-11 실행은 한국어·아랍어 각각 80개, 다른 11개 언어 각각 8개, 한국어의 다른 테마 3개에서 각각 80개, 태블릿 폭에서 8개를 실행해 **중복 포함 연습 496회·입력 632회**가 로그에 남았다. 모두 통과했다. 이는 고유 연습 수가 496개라는 뜻이 아니다.
- 2-21·2-22 같은 단위 검사의 통과와 위 UI 연결 오류는 함께 존재할 수 있다. 검사 함수가 올바른 입력을 받았을 때의 정답과, 실제 앱이 그 입력을 올바르게 만드는지는 별도다.
- 변형 정의 **57개 파일의 치환 기준 505개**가 현행 소스에서 각각 정확히 한 번 일치하는지 읽기 전용으로 대조했다. 누락·중복은 없었다. [상세 결과](test_output/chatgpt-review-20261018/mutation-anchor-compatibility.json). 이는 오래된 치환 기준 때문에 실행 자체가 깨지는지 확인한 것이며, 실제 소스 변형 주입과 505회 게이트 재실행을 수행했다는 뜻은 아니다.
